# Horizon Enhanced

Приватная сборка Horizon для macOS Apple Silicon и Windows x64. Здесь сохранены исходники, доработки рендерера, запускатели, рецепты профилей BSL и история разработки. Это независимая рабочая копия, не официальный релиз Horizon.

База: [horizon-rust/horizon, 1da354b](https://github.com/horizon-rust/horizon/tree/1da354b67a509812c4141b67de2affd6de65c342), Minecraft Java 26.3. Оригинальная документация — [README-UPSTREAM.md](README-UPSTREAM.md), лицензия Horizon — [LICENSE](LICENSE). Сохраняются авторство и права исходного проекта.

## Готовые сборки

Скачивайте ZIP из [Releases](https://github.com/Yan-L0/horizon-enhanced/releases). Текущая версия — **0.4.0**. Архив нужно полностью распаковать.

- Windows x64: запустить `Launch-Horizon.cmd`; соседние `.ps1`, `.exe` и `resources/` обязательны. На этом ПК должны быть подготовлены ресурсы Minecraft 26.3 через официальный Horizon launcher. Данные Enhanced хранятся отдельно в `%APPDATA%\Horizon Enhanced`.
- macOS arm64: открыть `Horizon Enhanced.app`. Подготовленные ресурсы закреплённой версии Horizon должны уже присутствовать на Mac. Данные — `~/Library/Application Support/Horizon Enhanced`.

В архиве исторических сборок есть старые версии, в том числе экспериментальный Upgrader. **В актуальной сборке Upgrader отключён.**

## Сохранённые изменения

- Прозрачность цветов, травы, дёрна и огня; тёмная обводка и трещины разрушения.
- Камера, история кадров, шумовая текстура, отдельные снимки глубины и фон неба для GLSL-паков.
- Исправленная камера теней из более новой Horizon с сохранением наших изменений точности и покачивания камеры.
- Пропуск лишних mip-цепочек только для доказанно безопасных чтений нулевого уровня.
- Отрисовка неба после непрозрачных блоков при проверенной независимости проходов: скрытое небо отсекается глубиной.
- Профили BSL Quality/Balanced r2: менее туманный Энд и подавление ложного подземного неба/лучей. Последнее является приближением по высоте и небесному освещению, а не восстановлением отсутствующих дальних блоков.
- Запускатели macOS/Windows, отдельные папки данных, сохранение настроек и Agent Control.

## Структура

- `crates/`, `tools/`, `docs/` — полные исходники Horizon с нашими текущими изменениями.
- [`enhanced/platform/`](enhanced/platform/) — актуальные платформенные запускатели.
- [`enhanced/profiles.py`](enhanced/profiles.py) — воспроизводимое создание профилей из собственной копии BSL 10.1.8.
- [`enhanced/validation/`](enhanced/validation/) — обезличенные результаты проверок и метаданные сборок.
- [`enhanced/docs/UPSTREAM-ANALYSIS.md`](enhanced/docs/UPSTREAM-ANALYSIS.md) — анализ новой nightly перед оптимизацией.
- [`enhanced/archive/upgrader/`](enhanced/archive/upgrader/) — сохранённый код отключённого порта Upgrader; не входит в игровой workspace.
- [`enhanced/archive/tooling/`](enhanced/archive/tooling/) — исторические скрипты и тестовые сценарии. Они сохраняют прежнюю структуру рабочей папки; это справочный архив, не готовая система сборки нового checkout.

## Сборка и проверки

Нужны актуальный Rust stable и платформенный linker. Для Windows MSVC можно использовать нативные Build Tools либо cargo-xwin с LLVM/LLD и Microsoft SDK. Клиент и контрольный инструмент:

```sh
cargo build --locked --profile fast -p horizon-client --bin horizon-client --bin horizon-ctl
```

При Windows MSVC-сборке использовался `RUSTFLAGS="-C target-feature=+crt-static"`. Для кросс-компиляции добавляется target `x86_64-pc-windows-msvc`; готовые файлы появляются в `target/<target>/fast/`.

Профили создаются без загрузок и без изменения оригинального ZIP:

```sh
python3 enhanced/profiles.py --bsl /path/to/BSL_v10.1.8.zip --output /path/to/private-profiles
```

Каждая запись генерируемых r2 ZIP сверена с содержимым выпущенных профилей 0.4.0. Сам BSL, ресурсы Mojang, миры и ключи в Git не хранятся. Для сборки архива положите оригинальный BSL и созданные профили рядом с запускателем в предусмотренную им папку ресурсов.

Для всех тестовых запусков используйте отдельные временные `HORIZON_HOME`, `HORIZON_LAUNCHER_HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `HORIZON_LAUNCHER_NO_SELF_UPDATE=1` и `HORIZON_NO_AUDIO=1`; реальные миры не используйте. Часть upstream-проверок требует локальных игровых данных и не запускается без них.

## Что проверено

macOS: 28 тестов рендерера на M2/Metal, Finder-запуск, копия пещеры, поверхность и сохранение настроек. В одном ракурсе пещеры без лимита кадров получено около 78 → 88 FPS; это не универсальная гарантия.

Windows x64: успешная компиляция, только системные DLL-импорты, запуск EXE в Windows 11 ARM VM, API запуска, PowerShell 5.1, пути с пробелами, миграция профиля. Ресурсы Windows nightly 9d979ca загрузились, DirectX 12 инициализировался, временный сервер принял игрока. Полная визуальная проверка шейдеров на настоящем Windows GPU ещё не выполнена: VM использовала Microsoft Basic Render Driver и исчерпала лимит теста.

## Дальнейшая работа

Новые согласованные изменения выполняются в этом checkout, проверяются, оформляются содержательными коммитами и отправляются в `origin/main`. Результаты и ограничения проверок фиксируются в описании коммита или документации. Upstream CI сохранён как исходный код, но Actions в этом приватном репозитории пока отключены: его окружение подготовки игровых ресурсов здесь не настроено.
